# Ariadne (아리아드네)

> 미궁 속 테세우스에게 실타래를 건넨 아리아드네처럼,
> 현대 생활 곳곳에 흩어진 서양 문화의 **흔적(trace)** 에서 **원천(source)** 까지 실을 이어 주는 앱.

**보기: https://jwj-nick.github.io/ariadne/**

---

## 무엇을 하는 앱인가

나이키, 아마존, 판도라, 아폴로 계획, 목성, 나르시시즘, 아킬레스건, 판도라의 상자, 희생양, 루비콘.
우리가 매일 마주치는 이름들 뒤에는 그리스·로마 신화, 성경, 서양사가 놓여 있다.

서양에서 자란 사람은 이것들을 "이야기"로 배운 것이 아니라 살면서 수백 번 마주치며 익혔다.
비서양권 사람에게 부족한 것은 자료가 아니라 **마주침과 원천 사이의 실**이다.
아무리 읽고 들어도 연결이 없으면 며칠 뒤에 사라진다.

이 앱은 그 실을 잇는다. 학습 단위는 "제우스 이야기"가 아니라
**"오늘 본 로고·용어·행성·그림·영화 뒤에 무엇이 있나"** 다.

## 화면

| 주소 | 하는 일 |
|---|---|
| `/` | 흔적과 원천 둘러보기. 검색과 갈래 필터 |
| `/trace/<slug>` | 흔적 카드. 원천으로 가는 실, 어디서 만나나, 왜 이 이름인가 |
| `/source/<slug>` | 원천 카드. 눈높이별 요약, 여기서 나온 흔적, 3문장 스토리, 관계 |
| `/quiz` | 오늘의 복습. **추측 → 힌트 3단 → 답 → 카드** 순서를 지킨다 |
| `/capture` | 조우 캡처. 폰 공유 시트로 던진 글에서 아는 흔적을 알아보고 오늘 복습에 넣는다 |
| `/settings` | 진도, 눈높이(아이/어른), 백업 내려받기와 되돌리기 |

## 설계에서 지키는 것

- **흔적이 1차 키다.** 원천은 흔적에서 도달하는 목적지다. 들어오는 흔적이 없는 원천은 감사에서 경고한다.
- **정답을 먼저 보여주지 않는다.** 스스로 떠올린 뒤에 답을 여는 순서를 UI 가 강제한다.
- **눈높이 두 단계.** 카드마다 아이용과 어른용 요약을 모두 갖춘다.
- **한국 대응물.** 가능한 카드에는 한국 문화의 대응물을 한 줄 붙인다.
  미다스의 당나귀 귀와 「임금님 귀는 당나귀 귀」, 시시포스와 밑 빠진 독, 루비콘과 배수진 같은 것들이다.
- **AI 는 꼭 필요한 곳에만.** 퀴즈와 힌트는 빌드 시점에 만들어 두고, 캡처 매칭도 먼저 글자로 맞춰 본다.

자세한 배경은 `docs/` 에 있다.
`00-MISSION.md`(왜 만드는가), `01-DESIGN-LOG.md`(결정 기록), `02-SCHEMA.md`(카드 규격),
`04-ROADMAP.md`(계획), `05-PROGRESS.md`(지금 어디까지 왔나) 순서로 읽으면 된다.

## 어떻게 만들어져 있나

콘텐츠는 `content/` 아래의 마크다운이 원본이고, 빌드가 이것을 `app/data/graph.json` 하나로 굳힌다.
앱은 그 파일만 읽는다. 데이터베이스에는 사용자 상태만 두고 콘텐츠는 두지 않는다.

```
content/traces/<category>/<slug>.md    흔적 카드
content/sources/<domain>/<slug>.md     원천 카드
scripts/                               감사 · 빌드 · 퀴즈 생성 · 아이콘
app/                                   Next.js App Router
tests/                                 단위 테스트 + E2E
```

Next.js 16, React 19, Tailwind 4. 학습 기록은 지금 브라우저의 `localStorage` 에만 있고,
저장 계층이 `app/lib/store/` 인터페이스 뒤에 숨어 있어서 나중에 갈아 끼울 수 있다.

## 돌려 보기

```bash
npm install
npm run dev        # build:content 를 먼저 돌린 뒤 개발 서버를 띄운다
```

| 명령 | 하는 일 |
|---|---|
| `npm run check` | 타입 검사 → 단위 테스트 → 콘텐츠 감사 → 빌드. **커밋 전 게이트** |
| `npm run verify` | 위에 더해 `next build` 와 E2E 까지. 화면이 바뀌었을 때 |
| `npm run audit` | 콘텐츠 감사 리포트를 `reports/` 에 남긴다 |
| `npm run test:e2e` | 빌드된 앱을 띄우고 브라우저로 확인한다. 스크린샷은 `tests/e2e/shots/` |

콘텐츠를 고칠 때는 `content/` 의 마크다운만 손대면 된다.
스키마 검사와 퀴즈 생성은 빌드가 알아서 따라온다.
