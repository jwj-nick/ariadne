# 01. DESIGN LOG — 오너 ↔ Claude 설계 대화 기록

> 형식: 각 라운드마다 오너의 발언 요지 → Claude의 제안 → 결정/보류. 이후 Claude Code 세션에서도 이 파일에 라운드를 추가한다.
> 결정(DECISION)은 번호를 붙이고 절대 삭제하지 않는다. 뒤집을 때는 새 DECISION으로 supersede 표기.

## Round 1 — 2026-09-06 (claude.ai 모바일)

### 오너
- 그리스로마신화, 기독교 성경 등을 **서양 지식인이 일반 교양으로 아는 수준**으로 쉽게 습득하고, 필요할 때 쉽게 찾아보고, 퀴즈로 익혀 나가고 싶다.
- 조금씩 읽고 방송에서 들어도 **기억에 잘 남지 않는다**. 외부 자료는 엄청나게 많다.
- 1차 버전을 만들고 계속 업데이트하며, **아이들과 나 같은 비서양권 성인**을 대상으로 하고 싶다.

### Claude 진단
- 자료 부족이 아니라 **연결 고리 없이 스토리만 흘러가서** 안 남는 것.
- 서양 지식인도 스토리 암기가 아니라 **일상 언어·예술·뉴스 속 비유(allusion) 단위**로 안다 (Achilles heel, Pandora's box, prodigal son, Judas kiss).
- 설계 축을 "이야기 읽기"가 아니라 **"비유 사전 + 조우(遭遇) 기반 학습"**으로.

### Claude 제안 (v1 골격)
- 단위 = 카드 1장 = 인물/사건/장소. 필드: 한 줄 정의 → 3문장 스토리 → *왜 알아야 하나*(관용구·영어 표현·그림·영화·브랜드) → 연결 노드 → 난이도/빈도.
- 빈도순 큐레이션: 영어 관용구 사전, 문학 인용 빈도. E.D. Hirsch *Cultural Literacy* 리스트 참고. 신화 100 + 성경 100.
- 저장: git Markdown + YAML frontmatter, `[[링크]]`, Obsidian 그래프. Claude Code로 생성·교차검증 파이프라인.
- 학습 루프: 오너가 별도로 구상 중인 **범용 학습 코어**(소크라테스식 문답, 생성 효과, 힌트만 주는 AI 튜터, 사람이 반드시 답함)의 첫 적용 과목. 카드 보기 전 추측 → 힌트 → 답 → 카드. SM-2 복습.
- 퀴즈 유형: 관용구→기원 / 그림·영화 장면→신화 / 가계도 빈칸 / 뉴스 문장의 비유 설명 / 신화↔성경 대응(대홍수, 저승 하강).
- 가족·비서양권: 카드마다 kid/adult 2단, 한·영 병기, 한국 문화 대응물 1줄 (예: 오르페우스 ↔ 바리데기).

### Claude 질문 3개
1. 범위: 신화·성경만? 셰익스피어·서양사까지 "서양 교양 전반"?
2. 입력 트리거: 방송·책에서 마주친 순간 폰 캡처 → 카드 매칭 → 저녁 퀴즈, 이 "조우 캡처"를 1차에 넣을지?
3. 배포: 본인용 Markdown+CLI 먼저 vs 처음부터 웹앱?

## Round 2 — 2026-09-06

### 오너 답변
1. 범위 = **후자 (서양 교양 전반)**.
2. 조우 캡처 = **아주 좋음, 넣는다**.
3. **처음부터 웹앱.** 오너는 이 주제를 CLI 텍스트로 살피고 싶지 않다. 단, 실제 작업은 Claude Code로 가져가야 하는지 질문.
- 추가 방향: 현대 사회·문명·경제·브랜드·프로젝트 네이밍·과학 용어·태양계 행성·회화·소설·영화 등 **너무나 광범위하게 녹아 있다** (클래식 포함). **현대인이 실제 삶에서 접하는 모든 것에 집중**해서 방향을 잡길 원함.

### Claude 제안 — 스키마를 뒤집는다
- 1차 키를 원천이 아니라 **흔적(trace)**으로. 흔적 노드(Nike, Amazon, Pandora 앱, Apollo, Trojan, Titan/Atlas, 목성·토성·유로파, Se7en, Prometheus, narcissism·siren·mentor·hermetic·nemesis·tantalize·jovial…) ↔ 원천 노드(신·인물·사건·개념).
- 연결 = "왜 이 이름이 붙었나" 1줄. 학습은 흔적→원천, 조회는 양방향.
- 카테고리 태그: 브랜드 / 과학·천문 / 심리·의학 / 회화·조각 / 문학·영화 / 정치·법 / 일상 관용구 / 프로젝트·제품 코드명.
- 역할 분리: **Claude Code = 콘텐츠 파이프라인·코드 공장**, **웹앱 = 소비·학습·캡처 표면**. 오너는 CLI에서 콘텐츠를 보지 않는다.
- 스택: Next.js + Supabase(가족 계정, SM-2 상태, 캡처) + Vercel. **PWA share target**으로 폰 공유 시트 캡처. 캡처 → Claude API 매칭 → 없으면 신규 후보 큐 → 저녁 퀴즈 데크 자동 편입.
- 화면 4개: 오늘의 조우 / 조회(검색+그래프) / 퀴즈 / 신규 후보 승인(오너 = 큐레이터).
- 개선 제안: 초기 200장을 손으로 고르지 말고 Claude Code로 **"흔적 수확기(trace harvester)"**를 먼저 만든다 — 브랜드 리스트, 원소·행성·위성 명명표, 심리학 용어집, 유명 회화 제목을 입력하면 원천 후보를 자동 추출·정렬.
